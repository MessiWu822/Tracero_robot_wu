# TC-01 从基础仿真环境复现碰撞失败

本文面向第一次运行 TC-01 的使用者。前置条件是已经完成
\`A-TurtleBot3仿真完整指南_Windows11_WSL2_Docker(1).md\`，并且能够启动
\`turtlebot3_src\` 容器和普通 TurtleBot3 Gazebo 仿真。本测试使用仓库中的
TC-01 专用覆盖配置，不修改 Nav2 源码，也不要求修改普通 TurtleBot3 启动文件。

## 1. 测试结果

测试要得到下面完整链路：

\`\`\`text
发送 NavigateToPose
  -> Burger 向 x 正方向直行
  -> Gazebo 与 tc01_wall 发生真实接触
  -> /tc01/bumper_states 发布碰撞双方
  -> controller 约 0.5 秒没有位移进展
  -> 无恢复行为树返回失败
  -> NavigateToPose 为 ABORTED，status=6
  -> Agent 保存 navigation_collision 和 navigation_failed
\`\`\`

墙体中心在 \`(0.60, 0.00, 0.00)\`。墙体的碰撞轨道只有 0.12 m 高，Burger
底盘能够真正撞上它。TC-01 overlay 关闭 local/global costmap 的动态
obstacle 和 voxel layer，并将 \`FollowPath.max_vel_theta\` 限制为 \`0.01\`，
避免机器人在墙前规划绕行或原地旋转。

## 2. 进入容器和检查文件

在 Windows PowerShell 中执行：

\`\`\`powershell
docker exec -it turtlebot3_src bash
\`\`\`

容器中必须存在以下目录：

\`\`\`text
/root/workspace/tracero_tc01
/root/workspace/tracero_agent_ws/src/tracero_agent
/root/workspace/tracero_agent_ws/src/tc01_auto_injector
\`\`\`

对应关系如下：

| 功能 | 仓库路径 | 容器路径 |
| --- | --- | --- |
| Nav2 overlay 和行为树 | \`robot/simulation/config\` | \`/root/workspace/tracero_tc01/config\` |
| 地图 | \`robot/simulation/maps\` | \`/root/workspace/tracero_tc01/maps\` |
| 启动、生成、清理脚本 | \`robot/simulation/scripts\` | \`/root/workspace/tracero_tc01/scripts\` |
| 墙体模型 | \`robot/simulation/models/tc01_wall\` | \`/root/workspace/tracero_tc01/models/tc01_wall\` |
| Agent | \`tracero_agent\` | \`/root/workspace/tracero_agent_ws/src/tracero_agent\` |
| 自动注入器 | \`robot/src/tc01_auto_injector\` | \`/root/workspace/tracero_agent_ws/src/tc01_auto_injector\` |

如果是从 Windows checkout 重新部署，保持上述目录内容与仓库一致，然后执行
第 4 节的构建命令。不要把 \`build/\`、\`install/\`、\`log/\` 或事件目录复制进
源码目录。

## 3. 每个终端的环境

推荐打开 5 个终端，每个终端都执行 \`docker exec -it turtlebot3_src bash\`。
Gazebo、Nav2、Agent 和观察命令必须使用同一个 \`ROS_DOMAIN_ID\`。

Gazebo/Nav2 终端执行：

\`\`\`bash
source /opt/ros/humble/setup.bash
source /root/turtlebot3_ws/install/setup.bash
source /root/nav2_ws/install/setup.bash
export TURTLEBOT3_MODEL=burger
export ROS_DOMAIN_ID=30
\`\`\`

Agent/注入器终端再执行：

\`\`\`bash
source /root/workspace/tracero_agent_ws/install/setup.bash
\`\`\`

\`/root/nav2_ws/install/setup.bash\` 不能省略，否则可能出现
\`package 'nav2_bringup' not found\`。所有节点必须使用仿真时间；Gazebo 的
\`/clock\` 是时间源。

## 4. 首次构建 Agent 和注入器

每次修改 Python、参数或 package.xml 后重新执行：

\`\`\`bash
cd /root/workspace/tracero_agent_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-select tracero_agent tc01_auto_injector
source install/setup.bash
ros2 pkg prefix tracero_agent
ros2 pkg prefix tc01_auto_injector
\`\`\`

构建末尾不能出现 \`error\` 或 \`failure\`。如果只修改了仓库文件但没有重新
构建并重启 Agent，运行中的节点仍可能使用旧的 install 内容。

## 5. 启动顺序

### 5.1 终端 1：Gazebo

\`\`\`bash
source /opt/ros/humble/setup.bash
source /root/turtlebot3_ws/install/setup.bash
export TURTLEBOT3_MODEL=burger
export ROS_DOMAIN_ID=30
ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py \
  x_pose:=-0.4 y_pose:=0.0
\`\`\`

等待世界和 Burger 出现，再检查：

\`\`\`bash
ros2 topic echo /clock --once
ros2 topic list | grep -E '^/(clock|scan|odom|cmd_vel)$'
\`\`\`

### 5.2 终端 2：TC-01 专用 Nav2 和 RViz2

\`\`\`bash
source /opt/ros/humble/setup.bash
source /root/turtlebot3_ws/install/setup.bash
source /root/nav2_ws/install/setup.bash
export TURTLEBOT3_MODEL=burger
export ROS_DOMAIN_ID=30
/root/workspace/tracero_tc01/scripts/launch_tc01_navigation.sh \
  /root/workspace/tracero_tc01/maps/turtlebot3_map_v2.yaml
\`\`\`

必须使用这个脚本，不能用普通 \`navigation2.launch.py\` 替代。脚本会自动
合并 \`tc01_nav2_overrides.yaml\`，并把
\`tc01_nav_to_pose_no_recovery.xml\` 设置为默认 NavigateToPose 行为树。

等待生命周期管理器完成激活后检查：

\`\`\`bash
ros2 lifecycle get /bt_navigator
ros2 action info /navigate_to_pose
\`\`\`

预期分别是：

\`\`\`text
active [3]
Action servers: 1
    /bt_navigator
\`\`\`

如果是 \`inactive [2]\` 或 \`Action servers: 0\`，不要发送目标；RViz 会报
\`Goal was rejected by server\`。等待启动完成或查看 Nav2 终端错误。

### 5.3 终端 3：Agent

\`\`\`bash
source /opt/ros/humble/setup.bash
source /root/workspace/tracero_agent_ws/install/setup.bash
export ROS_DOMAIN_ID=30
ros2 launch tracero_agent agent.launch.py
\`\`\`

Agent 默认将事件写入：

\`\`\`text
/root/workspace/tracero_agent_data/events
\`\`\`

如果后端 \`127.0.0.1:8000\` 没有运行，上传会有连接失败告警，但本地 JSON
仍会生成，不影响本地验收。

### 5.4 终端 4：观察碰撞

\`\`\`bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=30
ros2 topic echo /tc01/bumper_states
\`\`\`

没有碰撞时 \`states: []\` 是正常的；只有撞墙时才会出现碰撞名称。

## 6. 设置初始位姿

在 RViz 点击 **2D Pose Estimate**，将机器人定位到 \`map\` 中的
\`x=-0.40, y=0.00\`，朝向 x 正方向。也可以执行：

\`\`\`bash
ros2 topic pub --once /initialpose \
  geometry_msgs/msg/PoseWithCovarianceStamped \
  "{header: {frame_id: map}, pose: {pose: {position: {x: -0.4, y: 0.0, z: 0.0}, orientation: {w: 1.0}}}}"
\`\`\`

确认 TF：

\`\`\`bash
ros2 run tf2_ros tf2_echo map base_link
\`\`\`

如果提示没有 \`map\`，等待 \`/amcl\` 和 \`/map_server\` active 后重新发布。

## 7. 推荐方式：手动注入墙体

这种方式最容易复现，适合首次验收。先清理上一轮：

\`\`\`bash
/root/workspace/tracero_tc01/scripts/reset_tc01.sh
ros2 service call /tracero_agent/reset std_srvs/srv/Trigger "{}"
\`\`\`

生成墙体：

\`\`\`bash
/root/workspace/tracero_tc01/scripts/spawn_tc01_wall.sh
gz model -m tc01_wall -p
\`\`\`

预期模型位置接近 \`0.6 0 0\`。生成脚本成功后会自动调用
\`/tracero_agent/injection\`，把真实生成时刻作为 Agent 的事件时间锚点。

发送穿过墙体的目标：

\`\`\`bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
  "{pose: {header: {frame_id: map}, pose: {position: {x: 1.2, y: 0.0, z: 0.0}, orientation: {w: 1.0}}}}"
\`\`\`

Burger 应沿 x 正方向直行并撞墙。不要按 Ctrl+C，也不要 cancel goal；最终
必须看到：

\`\`\`text
Goal finished with status: ABORTED
\`\`\`

## 8. 可选方式：自动注入

自动方式保留“导航开始后才发生故障”的语义。启动注入器：

\`\`\`bash
source /opt/ros/humble/setup.bash
source /root/workspace/tracero_agent_ws/install/setup.bash
export ROS_DOMAIN_ID=30
ros2 run tc01_auto_injector tc01_auto_injector \
  --ros-args -p use_sim_time:=true
\`\`\`

重置并武装：

\`\`\`bash
ros2 service call /tc01/reset std_srvs/srv/Trigger "{}"
ros2 service call /tracero_agent/reset std_srvs/srv/Trigger "{}"
ros2 service call /tc01/arm std_srvs/srv/Trigger "{}"
\`\`\`

然后发送第 7 节相同目标。注入器等待 \`/cmd_vel.linear.x > 0.05\` 持续 1 秒，
成功生成墙体后自动通知 Agent。查看状态：

\`\`\`bash
ros2 service call /tc01/status std_srvs/srv/Trigger "{}"
\`\`\`

完成后应看到 \`injected: true\`、\`armed: false\`。

## 9. 验收证据

### 9.1 真实碰撞

\`\`\`bash
ros2 topic info /tc01/bumper_states --verbose
ros2 topic echo /tc01/bumper_states
\`\`\`

碰撞消息中应包含：

\`\`\`text
burger::base_link::base_collision
tc01_wall::wall_link::wall_collision
\`\`\`

### 9.2 Nav2 参数和生命周期

\`\`\`bash
ros2 param get /bt_navigator default_nav_to_pose_bt_xml
ros2 param get /controller_server progress_checker.movement_time_allowance
ros2 param get /controller_server progress_checker.required_movement_radius
ros2 param get /controller_server FollowPath.max_vel_theta
ros2 param get /local_costmap/local_costmap obstacle_layer.enabled
ros2 param get /local_costmap/local_costmap voxel_layer.enabled
\`\`\`

预期关键值为 \`0.5\`、\`0.02\`、\`0.01\`、\`False\`、\`False\`；行为树路径应指向
\`tc01_nav_to_pose_no_recovery.xml\`。生命周期检查：

\`\`\`bash
for node in controller_server planner_server behavior_server bt_navigator; do
  ros2 lifecycle get /$node
done
\`\`\`

关键节点应为 \`active [3]\`。

### 9.3 Action 和 Agent

\`\`\`bash
ros2 topic echo /navigate_to_pose/_action/status
ros2 service call /tracero_agent/status std_srvs/srv/Trigger "{}"
ls -lt /root/workspace/tracero_agent_data/events | head
\`\`\`

Action 最终状态 \`6\` 才是 \`ABORTED\`；状态 \`5\` 是 \`CANCELED\`，不能作为测试
失败结果。Agent 状态应包含 \`collision_detected: true\`，并且事件目录存在同
一轮的：

\`\`\`text
event_*_navigation_collision.json
event_*_navigation_failed.json
\`\`\`

两个 JSON 都应有 \`window.pre_5s\` 和 \`window.post_2s\` 数组。Agent 当前支持
排队，碰撞和 Nav2 failed 相隔不到 2 秒时也会保留两个事件。

### 9.4 可选 rosbag

正式记录建议同时保存传感器、运动、碰撞和 action：

\`\`\`bash
ros2 bag record --include-hidden-topics \
  /scan /odom /cmd_vel /local_costmap/costmap /global_costmap/costmap \
  /plan /tc01/bumper_states \
  /navigate_to_pose/_action/status /navigate_to_pose/_action/feedback
\`\`\`

## 10. 清理和重复运行

必须先等待 Agent 状态中的 \`pending_event: false\`，再重置：

\`\`\`bash
/root/workspace/tracero_tc01/scripts/reset_tc01.sh
ros2 service call /tracero_agent/reset std_srvs/srv/Trigger "{}"
\`\`\`

下一轮重新发布 \`/initialpose\`。结束测试时按 Ctrl+C 停止 rosbag、注入器、
Agent、Nav2/RViz2 和 Gazebo，确认没有残留 \`gzserver\`、\`nav2_container\` 或
旧 Agent 进程。

## 11. 常见问题

| 现象 | 处理 |
| --- | --- |
| RViz \`Goal was rejected by server\` | 检查 \`/bt_navigator\` 为 \`active [3]\` 且 action server 为 1；不要在激活前发目标。 |
| 机器人在墙前转圈 | 确认使用 \`launch_tc01_navigation.sh\`，并检查 \`max_vel_theta=0.01\`、两个动态层为 \`False\`。 |
| \`nav2_bringup not found\` | source \`/root/nav2_ws/install/setup.bash\`。 |
| \`Transform data too old\` | 检查 \`/clock\` 和全部 Nav2 节点 \`use_sim_time=True\`，重启 Nav2 后重新设置初始位姿。 |
| bumper 一直为空 | 检查墙体 z 为 \`0.0\`、接触插件存在，并确认 topic 有 publisher 和 Agent subscriber。 |
| 只有 collision 没有 failed | 重新 build 并重启当前 checkout 的 Agent，避免旧 install 或旧进程。 |
| 上传后端连接失败 | 本地 JSON 仍有效；后端可用时修改 \`tracero_agent/config/agent.yaml\` 的 \`backend_url\`。 |

## 12. 实现文件

- \`simulation/config/tc01_nav_to_pose_no_recovery.xml\`：只含规划和跟踪，不执行 Spin、BackUp、Wait 或 costmap clearing recovery。
- \`simulation/config/tc01_nav2_overrides.yaml\`：关闭动态障碍层、限制角速度，将 progress timeout 设为 0.5 秒。
- \`simulation/scripts/launch_tc01_navigation.sh\`：合并参数并启动 Nav2/RViz2。
- \`simulation/scripts/spawn_tc01_wall.sh\`、\`reset_tc01.sh\`：手动注入和清理。
- \`src/tc01_auto_injector\`：根据速度自动注入并通知 Agent。
- \`../../tracero_agent/tracero_agent/agent_node.py\`：记录 ContactsState、Nav2 action 失败和前后时间窗口。
